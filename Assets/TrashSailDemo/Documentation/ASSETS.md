# Imported assets and persistent ocean

## Import and setup

Run `TrashSailDemo.Editor.DemoAssetSetup.CreateOrUpdateAssets()` (menu **Trash Sail Demo / Create or Update Imported Assets**) after `AssetDatabase.Refresh()` and before the shared scene builder calls `DemoWorld.BuildVessel`. It idempotently creates textured HDRP prefabs in `Assets/TrashSailDemo/Imported/Resources/TrashSailModels/`. It does not change the render pipeline or package manifest. Original model files stay untouched. The lead owns serialized Unity imports and rendered verification.

`DemoAssetLibrary.InstantiateVisual(key,parent,layer)` loads the imported prefab; missing assets throw an actionable setup error rather than substituting a visible primitive. `CreateActor(key,kind,position,parent)` provides simulation bodies with hidden bounding-box acoustic/collision geometry. Only simulator generation, evaluation and truth-labelled spectator views may read actor identity.

## Provenance and files

The actual models and textures are local, not download placeholders. `Imported/asset-manifest.json` records download URL, creator, licence, SHA256, byte size and available source dimensions. `Tools/Assets/Download-Assets.ps1` downloads Poly Haven FBX 1k models and all API-listed includes with an identifying user-agent and MD5 verification. `Tools/Assets/Validate-Assets.ps1` checks all manifest SHA256 values and sizes.

## Materials and conversion

HDRP/Lit uses the downloaded diffuse colour and OpenGL normal maps, with 1k maximum texture sizes. Poly Haven roughness is converted into HDRP mask alpha = 1 - roughness; metallic is a declared material approximation (0.6 for the tin, zero for the plastic/bag). Fish packed glTF metallic-roughness is converted with blue ? metallic and green ? roughness. Mask G/B are one (no separate occlusion/detail mask). Source appearance is retained; no orange heuristic recolouring is used. `HDRP/Lit` must exist in the installed host.

`BarramundiFish.glb` is the 12,488,144-byte Khronos sample. It has **zero skins and zero animations**, 2,188 vertices and 3,864 polygons. `Tools/Assets/convert_fish.py` converts it to native FBX and extracts/resizes textures via official Blender 4.5.9 LTS, whose downloaded ZIP was checked against the official SHA256 file. Motion is a scripted rigid fish, not a claimed skeletal swimming animation. The conversion and source inspection reports are retained. Blender is an offline preparation tool, not a runtime dependency. Its portable download/cache under `Tools/Assets/blender*` is not intended for a source commit.

## Boat and compact scenarios

`DemoWorld.BuildVessel` keeps the physics root, conservative twin-hull collider envelope, sensor mounts, collector trigger/storage/gate, and caller signature. The visible hull/deck/mast/sail/rudder body is replaced with the imported MARUS boat. Collection guides and sensor housings remain original simple engineering hardware. The imported monohull is a visual proxy; the preserved wider collision envelope and lead-owned thruster/mass parameters are provisional and must be matched to future CAD. No sail geometry implies an active sail drive in the production twin-thruster branch.

Compact tests use imported gallon bottle, tin and bag; unknown-labelled packaging uses the same genuine bag geometry/material and does not manufacture a colour-based operational class. Fish crossing remains an independent fixed path, exits at X=12, and does not evade the vessel. Fixed test occluders may remain simple geometry. Rubbish buoyancy is a spring/damper at an approximate waterline; acoustic colliders are coarse boxes. Neither fish motion nor scattering is biologically/physically validated.

## Ocean records and streaming

`OceanPopulation` exposes `Config`, `Vessel`, `IReadOnlyList<OceanRecord> Records`, `ActiveCount`, `ActivationRadius`, `ResetPopulation(seed)`, and `ClearPopulation()`. `OceanRecord` holds `Id`, `Kind`, `AssetKey`, `InitialPosition`, `Position`, `Velocity`, `Rotation`, `Collected`. These are **simulation truth**, available only for world generation, scoring, streaming and an explicitly labelled full-world spectator overview. Navigation must not use this collection.

Defaults are 350 rubbish items, 16 fish and 5 static background boats over Config.MissionWidth × MissionLength (1000 × 1000 m). Seeded groups mix isolated objects and small clusters with random yaw. If ReachableDemoSeed is enabled, the first three items are fixed at X=0/Z=35,70,110 before the mission starts; their drift is zero. The rest receive small seeded drift. This is a documented favourable demonstration seed, independent of camera visibility and route execution; items are never moved into view for detection.

Local actor pooling activates within the greater of StreamingRadius (100 m default) and sonar range plus vessel length, margins, eight seconds of configured search movement and 8 m manoeuvring allowance. Deactivation has 20 m hysteresis. Pooling avoids repeated mesh/body creation; imported visual LODGroups cull tiny screen footprints without substituting a primitive. There are no separately decimated mesh levels. Full records persist and drift while inactive. Records synchronize to active physical bodies; fish follow configured velocity/boundary reflection independent of the vessel. Background boats are static obstacles.

The collector's physical capture callback marks the matching record collected only after entry, including fish bycatch. Captured objects remain in storage until reset and are never resurrected by streaming. Reset releases active/storage actors into per-asset pools, clears all records and counters via Vessel.ResetPose, re-seeds population and reconnects exactly one collection callback. The caller must call DemoWorld.ClearWorld() before enabling large-ocean mode, and ClearPopulation before switching back. Root/source meshes and materials persist across resets.
